# Installer protocol and recovery contract

The canonical implementation is `e5-linux/installer`. `sync.py <mu300-repository>` generates the other repository's mirror and `SHARED-SOURCE.json`. Edit the canonical source, synchronize, and run `--check`. Do not independently maintain two frontends/state machines. Both builds use the same Tauri executable and backend; repository-specific behavior is in `backend/adapter.py` and the existing Python/device scripts.

Protocol 1: one JSON object per line on stdin/stdout. A request is `{"protocol":1,"id":1,"command":"hello","params":{}}`. Responses contain the same `id`, `type:"response"` and `data:{ok,result}` or `{ok:false,error}`. Events use `type:"transaction"`, `"transfer"`, `"log"`. No terminal-text matching. Legacy stdout/stderr is suppressed; named observer callbacks produce events.

Commands are allowlisted in both Rust and Python: hello, snapshot, list, package, devices, probe, probe_update, plan, start, resume, retry, cancel, can_close, export, import. There is no shell/exec command. A frontend-selected serial is checked against an actual device. All ADB operations use that serial; eMMC CID and profile are rechecked after reset. SSH maintenance binds the key fingerprint between planning and execution; final verification binds the hardware CID. A plan cannot become executable without `confirmed:true` on its persisted transaction ID.

Transactions include format/version, device identity/profile/original slot/storage geometry, selected method/allocation, original partition layout, content-based payload identity, backups, legacy transaction path, completed effects, started/done mutation ledger, current stage/status and final measured result. Writes use flush/fsync plus atomic replacement. Per-CID and per-serial OS locks are shared between repositories. Kernel-released locks survive abnormal process termination correctly. Device scripts retain their own upgrade/partition locks.

Statuses: ready, running, waiting_user, waiting_device, failed, cancelled (a resumable pause), completed. Stages are independent of frontend navigation. Waiting for Android initialization, ADB authorization or root has no transaction deadline. Expected reboot is checkpointed before the reboot command. Every write has a stored intent and a completion checkpoint; completed effects are skipped. Uncertain nonrepeatable writes stop for readback/recovery. Existing backend transaction/geometry/token checks remain authoritative during stage-two resume.

Safety boundaries are before effects and between verified transfer chunks. Cancellation is requested, not process termination. Close is blocked for active operations; the user first requests a pause. If the host disappears during an unsafe operation, the ledger retains the incomplete intent. Reconnecting is not permission to repeat GPT shrink/format. Backups must be exported before reinstalling Windows or deleting app data. Device-only recovery with insufficient identity/layout/backup evidence is refused.

Transfer events contain `name`, actual acknowledged `bytes`, `total`, and `bytes_per_second`. Check/format/shrink/grow only emit phase and activity. Final verification reads an ext4 superblock over SSH base64, checks the expected allocated byte count and running OpenWrt, and reports filesystem bytes separately from partition size. No `od` or SFTP is required by that verification.

Content compatibility binds adapter, profile, root layout, kernel family and critical boot/rootfs/filesystem-tool hashes. Package paths and GUI/host-script versions are not compatibility keys. Package checksums are verified again on resume. This is integrity against corruption and accidental mismatch, not a signed release authenticity mechanism.
